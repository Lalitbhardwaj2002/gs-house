9. **Sixth request (13 November 2026): Pause and Submit in the quiz, solo and team; the text-size control "is not working".**
   - **Text size.** Cause: `--fs` scaled only the question, the explanation and the notes, so on the home screen, the lists and the menus the A− / A+ buttons changed nothing. Now every `font-size` in `style.css` is `calc(Npx * var(--fs))` (the print rules keep their `pt` sizes), so the whole app follows the control. The steps run from 50 to 150 per cent in tens (the owner's third and final list; a size saved by an earlier version moves to the nearest step) and the menu shows the present size between the two buttons. A new font size in the stylesheet must be written the same way. Checked at 140%, the largest size of the first version, on a 375 px screen: no screen scrolls sideways.
   - **Pause** (`pause` / `resume` actions; `pauseQuiz`, `resumeQuiz`). Only whoever runs the quiz can use it: the solo player, or the host of a room, where it pauses for everyone. The host state keeps `paused` and `pauseLeft` (time left on the clock); `endsAt` is 0 while paused, so the lock timer cannot fire. While paused the question is hidden behind a "Quiz paused" card (so a pause is not thinking time), answers and *Next* are refused, and guests see who paused. The client moves `local.shownAt` forward by the length of the pause, so answer times do not include it. A paused quiz survives a page reload. Key **P** pauses and resumes.
   - **Submit** (`submit` action; `submitQuiz`). Ends the quiz at once and shows the results, after a short question ("Submit the quiz?") in the app's own dialog. The owner did not want the browser's confirm box (dark, headed with the site's address), so `askConfirm()` draws a small dialog in the app's colours; Leave (✕) uses it too. It returns a promise, swallows the quiz keys while open, and closes on Escape or a tap outside. Only the questions reached are counted: the one on screen counts if somebody has answered it or its time is up, otherwise the quiz ends with the question before it (the first question always counts). The state is cut to that length (`qids`, `total`) and `planned` keeps the intended length; the results screen shows "Submitted early: a of n questions". Questions that were never shown are not marked as seen, and a quiz submitted early does not set a chapter's best score in the book companion.
   - In a room a guest has neither button; the host ignores `pause`, `resume` and `submit` from anyone else. Tested with two browser tabs as host and guest.
   - The pause card has no entrance animation on purpose: an element that starts at opacity 0 stays invisible on a page whose animations are not running.

## 6. How the app works (for whoever edits it)
- `sections.js`: UNITS and SECTIONS (id, unit, tracks `tgt`/`higher`, English/Hindi titles, scope).
- `data/<id>.json`: checked questions; `data/index.json`: counts (from `tools/build_index.py`). Question format: see `docs/example-question.json` and the brief.
- `app.js`: host-authoritative engine. Solo runs the host locally with no network. Rooms use PeerJS (`gshouse-v1-<CODE>`), up to 20 players. The host loads only the chosen sections, picks questions evenly across them (preferring ones this device hasn't seen, stored in localStorage `pp-seen`), sends each question once (`type: 'question'`), and small status updates (`type: 'state'`). Players get instant green/red feedback from the question data. At the end the host sends each player's report; each device builds its own answer sheet from the questions it received.
- `PUBLIC_URL` in `app.js` is the future GitHub Pages address (used for invite links when hosting from localhost).
- Interface added on 13 November 2026 (`app.js`, `style.css`; service-worker cache `gshouse-v6`):
  1. The **Next question** and **Start quiz** buttons sit in a bar that stays at the bottom of the screen (`.sticky-bar`).
  2. **About each option** is folded by default (`<details class="more">`); the device remembers if the player opens it (`pp-notes`). The option text is no longer repeated in the notes.
  3. **Quick practice** on the setup screen: saved questions (`pp-marks`, the ☆ button on a question) and past mistakes (`pp-wrong`). Both use the host message `{type: 'quick', qids}`; `startQuiz(only)` runs a fixed list of question ids.
  4. Results (solo): **Retry missed questions**, and the five weakest sections as buttons that start a quiz on that section (`{type: 'quick', sections}`).
  5. Results show accuracy **by unit** first; the full section list is folded.
  6. **Progress**: the last ten quizzes on the device (`pp-history`) as a bar chart with accuracy by unit, on the home and results screens.
  7. Answer sheet: filters (all / wrong / skipped / saved), number buttons to jump to a question, option notes on or off (always printed).
  8. **Keyboard**: A–D or 1–4 answer, Enter / N / → next.
  9. **Wide screens (960 px and up)**: sections beside the settings, explanation beside the question.
  10. Settings menu (⚙): sound, **dark mode** (`pp-theme`; follows the device until set), **both languages** (`pp-both`), **text size** (`pp-fs`; scales every font size in the app, 50% to 150%). All colours are CSS variables; the dark theme only swaps their values. Tap targets are at least 44 px and level chips follow the interface language.
  A short quiz over many sections now samples the sections in random order (before, a 10-question quiz over all sections used only the first ten).
